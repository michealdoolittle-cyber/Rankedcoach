# RankedCoach Non-Index Text Master Cheat Sheet — 2026-07-22

**Status:** Master editing/reference document.

**Scope:** User-facing or near-user-facing text that does **not** primarily live in `public/index.html`.

**Includes:** The previous Library 1:1 swap sheet from `notes/library-copy-swap-sheet-2026-07-22.md`, plus the main non-index copy homes: `public/app.js`, coaching language modules, Library modules, Riot/Henrik sync modules, legal pages, and daily/loading surfaces.

## How to use this document

Use this as the text-edit map before changing source files.

1. Find the surface you want to change.
2. Open the listed file and search the listed anchor or exact current sentence.
3. Replace only the intended sentence/field.
4. Keep data fields intact unless this sheet says the change is a field removal.
5. After source edits, run the matching validation:
   - `node --check public/app.js` after app copy edits.
   - `node --check public/library/gamesense-library.js` after Library renderer edits.
   - `node --check public/integrations/riot-sync.js` after client sync edits.
   - Browser console check before any deploy.

## Golden rules for text edits

- Do not move `id`, `key`, `category`, `condition`, `sourceRule`, or storage constants just to change wording.
- Prefer replacing the visible sentence, not the data model.
- For coaching advice, separate what data proves from what the app is assuming.
- Do not add rank/pro/team comparisons unless the code has a fresh source available in the current context.
- Do not hardcode missing stats to sound confident. If data is unavailable, say unavailable.
- For Riot/Henrik errors, keep raw technical error text server-side/log-side only; user-facing copy should be friendly.

## `public/analytics/coaching-rules.js` cheat sheet

Anchor: `RULES`

This file mostly controls whether a coaching rule is active, policy-only, or blocked. It is not where most visible sentences live, but its `reason` fields can appear in audits/dev explanations and are important context.

Editable fields:

| Field | Safe to edit? | Notes |
| --- | --- | --- |
| `reason` | Yes | Wording only, if the rule meaning stays the same. |
| `minMatches` / `minLogs` | Only with product decision | Changes behavior. |
| `status` | Only with verified data support | `blocked` means the data does not exist or should not be claimed. |
| `condition` | Avoid unless changing evaluator logic | Must match evaluator branches. |
| `sourceRule` | No, unless source docs are renumbered | Keeps traceability to language-rule docs. |

Current policy/blocker reason examples:

| Rule id | Current reason |
| --- | --- |
| `map-tiny-sample` | `Suppress map claims below three matches.` |
| `map-no-forced-outlier` | `Do not manufacture a map read when no useful outlier exists.` |
| `weapon-hs-context` | `Use the existing weapon-adjusted headshot weighting.` |
| `weapon-small-sample` | `Use category coaching until a weapon has enough rounds.` |
| `utility-timing` | `Henrik provides cast counts but no cast timestamps.` |
| `utility-agent-context` | `Never compare utility casts across agents as a flat rate.` |
| `utility-economy-context` | `Do not judge lower cast volume without economy context.` |
| `utility-unavailable-copy` | `State unavailable timing plainly and never estimate it.` |
| `team-confidence-cap` | `Team reads remain lower confidence than individual evidence.` |
| `comms-proxy-only` | `Use player-authored logs as a proxy; never imply voice-chat access.` |
